# Syntax Tree Editor Standalone

> 一个零依赖、免构建的语法树编辑器：图形和代码双向同步。

一个**图和代码双向可编辑**的语法树组件。零依赖、无构建步骤、纯原生 ES Modules。

- 在图上点选、双击改名、Tab 下移 / Shift+Tab 上移、快捷键增删节点
- 下面的括号记法跟着变；反过来直接改代码，图也立刻跟着变
- 导出独立 SVG（矢量，可插进 Word / LaTeX）和 2 倍分辨率 PNG

![截图](docs/overview.png)

*上图就是直接用 `file://` 打开 `standalone.html` 截的 —— 也就是双击的真实路径。*

## 为什么不是改 jsSyntaxTree

文件夹里那份 `jssyntaxtree-master/` 是**只读输入**的生成器，它的架构从根上就没法"可编辑"：

| 原项目的做法 | 为什么挡住了交互 |
| --- | --- |
| 渲染到 Canvas 2D | 节点只是画上去的像素，没有 DOM 对象、无法命中检测、无法双击改名 |
| 每次 `draw()` 全量重算重绘 | 节点没有稳定身份，选中态 / 编辑态无从挂载 |
| 只有 `文本 → 树` 单向 | 没有序列化器，图上的改动无法回写代码 |
| 布局是私有方法 `#layout` | 外部拿不到布局结果，没法在它上面叠交互层 |

所以这里保留了它**通行的括号记法**（沿用 phpSyntaxTree / jsSyntaxTree 的事实标准，本身是格式而非代码），
以及"母亲节点居中于女儿节点"的 tidy tree 思路，其余全部重写。

⚠️ 许可证：原项目是 **GPL-2.0**（传染性）。本编辑器是独立实现，**不包含原项目源码**，
因此不受其许可证约束。但如果你打算把原项目那份代码直接拷进来用，GPL-2 的义务就回来了。

## 跑起来

**方式一（推荐，双击即用）**：直接双击 `editor/standalone.html`。

它是把 CSS 和所有模块内联进一个普通 `<script>` 的构建产物，所以不受 `file://` 的
CORS 限制，双击就能打开，不需要任何服务。

**方式二（改代码时用）**：ES Modules 不能走 `file://`，必须起一个本地服务：

```powershell
cd editor
python -m http.server 8123
# 然后打开 http://127.0.0.1:8123/
```

> ⚠️ **双击 `index.html` 会是一片空白** —— 浏览器对 `file://` 下的 ES Modules
> 一律拒绝加载，JS 一行都不执行，编辑器区域就是空的、按钮也没反应。
> 改了 `src/` 里的代码之后要重新构建单文件版：`node tools/build-standalone.mjs`

## 单文件版（发给别人用这个）

`Syntax Tree Editor Standalone.html` 是交付物：**7 个模块全部内联在这一个文件里**，
所以它可以直接双击打开，不需要联网、不需要起服务器、不需要 ES Modules 支持。

- 改完 `src/` 或 `index.html` 之后必须重新构建：`npm run build`
- 它里面对外链的样式和脚本一个都没有，拷走一个文件就是完整的一份
- 和 HTTP 版**功能完全一致**，唯一区别是顶部那段"必须通过 HTTP 打开"的提示会被整段删掉 ——
  单文件版的用户已经在用单文件了，那段提示是噪音
- `npm test` 会验证磁盘上这份就是重新构建的结果，防止改了源码忘记构建

## 当组件用

```js
import { SyntaxTreeEditor } from "./src/editor.js";

const editor = new SyntaxTreeEditor("#container", {
  value: "[S [NP [D the][N dog]][VP [V barks]]]",
  fontSize: 16,
  fontFamily: "sans-serif",
  colors: true,          // 叶子红、非叶子蓝
  triangles: true,       // 含空格的叶子画成三角
  terminalLines: true,   // 是否画到叶子的连线
  showText: true,        // 是否显示代码面板
  onChange: ({ text }) => console.log(text),
});
```

| 方法 | 说明 |
| --- | --- |
| `setValue(text)` | 用括号记法设置整棵树；传空字符串会清成**空白画布**。会清空撤销历史 |
| `loadValue(text)` | 同上，但**保留撤销历史** —— 载入后按 Ctrl+Z 能退回载入之前。示例按钮用的就是它 |
| `getValue()` | 导出为括号记法；空白画布返回空字符串 |
| `clear()` | 清成空白画布 |
| `isEmpty` | 当前是不是空白画布（只读） |
| `createRoot(label)` | 在空白画布上创建根节点并进入改名；已有树时只做选中（幂等） |
| `setOptions(patch)` | 运行期改外观（字号、字体、颜色、三角、对齐…） |
| `setAlign(mode)` | 切换垂直对齐：`"depth"` / `"leaves"` / `"compact"` |
| `setTextMode(mode)` | 切换代码框的记法：`"bracket"` / `"rules"` |
| `getRules()` / `setRules(t)` | 用规则记法读写整棵树 |
| `toSvgString({background})` | 导出独立 SVG 字符串 |
| `exportSvg(name)` / `exportPng(name, scale)` | 触发下载 |
| `undo()` / `redo()` | 撤销 / 重做 |
| `addChild()` / `addSibling()` / `remove()` / `setLabel(t)` | 结构编辑，都作用于当前选中的节点 |
| `addLevel()` / `collapseLevel()` | 下移（加一层投射）/ 上移（去掉上面那层投射） |
| `moveRight()` / `moveLeft()` | 左移 / 右移（各有换位和换妈妈两个分支），见下 |

## 快捷键

先在图上点一下取得焦点。工具栏每个按钮**下边也标了对应的快捷键**。

| 键 | 动作 |
| --- | --- |
| <kbd>Enter</kbd> | 加一个**女儿**节点（最常用） |
| <kbd>Shift</kbd>+<kbd>Enter</kbd> | 加一个**姊妹**节点 |
| <kbd>Tab</kbd> | **下移**：加一层投射（见下） |
| <kbd>Shift</kbd>+<kbd>Tab</kbd> | **上移**：去掉紧挨着自己上面的那层投射 |
| <kbd>F2</kbd> 或双击 | 改名 |
| <kbd>↑</kbd> / <kbd>↓</kbd> | 跳到母亲节点 / 跳到最左边的那个女儿节点 |
| <kbd>←</kbd> / <kbd>→</kbd> | 跳到左 / 右姊妹节点；已经到边了就跨到**堂表姊妹节点**（范围和 <kbd>Alt</kbd>+<kbd>←</kbd><kbd>→</kbd> 一致） |
| <kbd>Alt</kbd>+<kbd>←</kbd><kbd>→</kbd>（或 <kbd>Ctrl</kbd>+<kbd>←</kbd><kbd>→</kbd>） | 左移 / 右移，见下 |
| <kbd>Delete</kbd> | 删除节点及其子树 |
| <kbd>Ctrl</kbd>+<kbd>Z</kbd> / <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Z</kbd> | 撤销 / 重做 |

>
> 左右移同时绑了 <kbd>Alt</kbd>+<kbd>←</kbd><kbd>→</kbd> 和 <kbd>Ctrl</kbd>+<kbd>←</kbd><kbd>→</kbd>。
> 原因是 Chrome 把 <kbd>Alt</kbd>+<kbd>←</kbd><kbd>→</kbd> 当成"后退/前进"，网页不一定拦得住。

## 下移 / 上移（加减投射层）

这是 X-bar 那套「加撇」的操作。

**下移**（<kbd>Tab</kbd>）沿 **加 ' 链** 往上找：只要爸爸的标签正好是自己加一个撇，就继续往上。
然后在**链顶之上**插一层，新层标签 = 链顶 + 一个撇。被选中的节点连同整条链一起下移一层。

```
[XP [Z word1] [X'' [X' [X word2]]]]      对 X 按 Tab
[XP [Z word1] [X''' [X'' [X' [X word2]]]]]
```

注意插入点在**链顶之上**（上例里是 X'' 的位置），不是紧挨着选中的 X。

**上移**（<kbd>Shift</kbd>+<kbd>Tab</kbd>）是它的逆：如果**母亲节点只有你这一个女儿节点**，
而且**母亲节点的标签正好是你加一个撇**，就把母亲节点删掉、你顶替它的位置，
再把母亲节点以上的每一层各减去一个撇。

```
[XP [Z wordZ] [X'' [X' [Y wordY] [X wordX]]]]   对 X' 按 Shift+Tab
[XP [Z wordZ] [X' [Y wordY] [X wordX]]]
```

上例里对 `X''` 不能上移（母亲节点 XP 不是 `X'''`），对 `X` 也不能（母亲节点 `X'` 还有另一个女儿节点）。

> **上下移要在不同的节点上操作才是严格互逆的**：下移插在链顶之上，所以要撤回去，
> 应该对着**下移之前的那条链顶**按 Shift+Tab（上例里是 `X''`），而不是对着原来选中的 `X`。
> 对 `X` 按 Shift+Tab 会删掉 `X'` 那一层。

投射链的最顶端就是根时无法下移；母亲节点标签不符合加撇规律时无法上移。两种情况按钮都会禁用。

### 改名框里的撤销

按 <kbd>F2</kbd> / 双击 / 新建节点后会弹出改名框，此时 <kbd>Ctrl</kbd>+<kbd>Z</kbd> 也能用，
而且是分两步的，符合直觉：

1. 如果你已经改过标签 → 先把标签恢复原样，**留在框里**继续编辑
2. 如果标签没动过 → 退出编辑，并**直接撤销掉"新建这个节点"那一步**

所以"手滑点出一个新节点"只要按一次 <kbd>Ctrl</kbd>+<kbd>Z</kbd> 就干净了。

## 垂直对齐

工具栏下面有 **按层级 / 词对齐底部 / 整树贴底** 三个按钮（也可以 `align: "depth" | "leaves" | "compact"`）。
用「移位例句」（`what_i is_j a syntax tree t_j t_i`）最容易看出区别 ——
在「按层级」下，每个词待在自己那一层；切到另外两种，所有词会一起落到底线：

| 模式 | 效果 | 截图 |
| --- | --- | --- |
| `depth` 按层级 | 每个节点都待在自己的层级行上，同层等高 | `docs/align-depth.png` |
| `leaves` 词对齐底部 | 所有叶子（词）落到最下面一行等高，中间节点保持原来的层级 | `docs/align-leaves.png` |
| `compact` 整树贴底 | 叶子对齐到底部后，中间节点也尽量下移贴着子节点，整棵树压到底线 | `docs/align-compact.png` |

三种模式只改变**纵向**位置，横向布局完全一致（有测试固定这一点）。

## 只有词才染红

红色不是"所有叶子"，而是**词**。判断标准是它在记法里写成裸标签 ——
也就是**它是母亲节点唯一的女儿节点**（或者它带位移箭头，因为带箭头的叶子节点必须裸写）。

用方括号包起来的空节点表示"没有展开的范畴"，跟非叶子一样是蓝色。

```
[XP [D [X'' [X word] [Y]]] [X']]
              └─ 红 ─┘   └ 蓝 ┘  └ 蓝 ┘
```

这条规则完全由结构决定，不依赖手写写法，所以往返之后不会变（有测试固定）。

## 左移 / 右移

两个操作作用在**选中的那个节点**上，**完全对称**，各自分两种情况：

| | ① 有同侧姊妹 | ② 自己是最边上的女儿 |
| --- | --- | --- |
| **左移** <kbd>Alt</kbd>+<kbd>←</kbd> | 和**左**姊妹节点交换位置（原地左挪一位） | 搬到「母亲节点的**左**姊妹节点」底下，当它的**最右边**的女儿节点 |
| **右移** <kbd>Alt</kbd>+<kbd>→</kbd> | 和**右**姊妹节点交换位置（原地右挪一位） | 搬到「母亲节点的**右**姊妹节点」底下，当它的**最左边**的女儿节点 |

拿首页那句举例：

```
[CP [C that] [TP [N Chomsky] [T' [T will] [VP [V love] [N AI]]]]]
```

选中 `T`：

```
左移 T —— T 是 T' 的最左女儿，走 ②，搬到 T' 的左姊妹 N 底下
  [TP [N Chomsky] [T' [T will] [VP ...]]]
  [TP [N [Chomsky] [T will]] [T' [VP ...]]]

右移 T —— T 有右姊妹 VP，走 ①，原地换位
  [T' [T will] [VP ...]]
  [T' [VP ...] [T will]]
```

再选中 `VP` 左移（VP 有左姊妹 T，走 ①）—— 结果和「右移 T」是**同一棵树**，这就是对称。
选中 `Chomsky` 右移（它是 N 的最右女儿，走 ②）—— 搬到 N 的右姊妹 T' 底下当最左女儿。

两条都不成立时（既没有那一侧的姊妹节点、母亲节点也没有那一侧的姊妹节点）按钮禁用、按键无效。


## 空白画布

`new SyntaxTreeEditor(el, { value: "" })` 或者运行期 `editor.clear()` 就得到一块空白画布：
没有任何节点，只有一层引导提示。从零开始的路径都是通的：

- 点画布任意处 / 按 <kbd>Enter</kbd> / 点"＋创建根节点" → 建出根节点并直接进入改名
- 空白画布上直接点范畴按钮（S / NP / VP…）→ 用它当根节点起一棵树
- 清空代码框 → 回到空白画布
- 根节点没有子节点时按 Delete → 回到空白画布（可以撤销回来）
- 根节点只有一个子节点时按 Delete → 把子节点提上来（等价于去掉这层括号，无损）
- 根节点有多个分支时不允许删（删了没法安置其余分支，按钮会禁用）

## 两套记法

代码框上方有 **括号记法 / 规则记法** 两个按钮，随时切换。模型不动，只是换个写法，所以切换是无损的。

### 括号记法

| 写法 | 含义 |
| --- | --- |
| `[S [NP Dogs][VP barks]]` | 方括号是节点，裸标签是叶子 |
| `[N_s Dogs]` | `_` 下标（写在**标签之后**，不是 `]` 之后） |
| `[N^s Cats]` | `^` 上标 |
| `["Main clause" [S][V][O]]` | 标签含空格时用双引号 |
| `[S NP VP]` | 多词叶子，会被画成三角（表示省略的下层） |
| `[A [B C][D E][F G ->6]]` | `->` + 节点编号（根为 0），画位移箭头（`-->` `<-` `<>` 是旧写法，仍能读入） |

### 规则记法

一行一条 mother → daughter 的边。下面这棵树：

```
[XP [D w1] [X' [X w2] [Y w3]]]
```

写成规则记法是：

```
0 XP -> D
0 XP -> X'
1 D -> w1
2 X' -> X
2 X' -> Y
4 X -> w2
5 Y -> w3
```

每行是：**母亲节点编号　母亲节点标签　->　女儿节点标签**。

- **根节点的编号固定是 0。**
- **其余节点的编号 = 它第一次出现在箭头右边的那一行的行号。**
  行号显示在代码框**左边的装订线上**（像 VS Code 那样，不在文本里，选中复制不会带上它）。
  装订线给**每一行**都编号，包括空行和箭头行。
- 母亲节点必须先用过才能引用（编号比当前行号小）。同一个母亲节点的行不必连续。
- **因为编号就是行号，在中间插一行或删一行会让下面所有引用错位 ——
  编辑器会自动把编号改回正确值**（只改行首那个数字，光标位置保留）。
- 标签含空格、引号、`_` 或 `^` 时用双引号括起来；下标上标写在标签后面，
  例如 `NP_1`、`N^s`、`"the mailman"_1`。
- 从别处粘过来的文本如果编号已经错位，解析时会先按标签把它们找回来，然后编辑器再把编号修好。

上面那棵树的编号是 `XP=0 D=1 X'=2 w1=3 X=4 Y=5 w2=6 w3=7`（就是装订线上的 1–7）。

位移箭头单独成行，放在最后：

```
7 --> 6
```

意思是"编号 7 的节点移到编号 6 的位置"。**起点必须是叶子**（记法里箭头挂在叶子上，比如 `t`），
落点可以是任何节点，包括根（`--> 0`）。

### 装订线（行号列）

规则记法下的行号是一个**独立的、只读的**元素，不是文本的一部分：

- 不可选中（`user-select: none`），框选复制拿到的只有规则本身
- 不接收键盘焦点，点它只会把焦点交给文本框，光标行为跟 VS Code 一致
- 随文本框滚动同步

括号记法下不显示（那里的行号没有含义）。

### 两套记法共用同一套编号

括号记法里的 `->N` 和规则记法里的 `A --> B`，其中的 N 是同一个意思 —— **根为 0、其余按首次出现行号**的编号。
所以同一个箭头在两边的数字相同，来回切换不会看花眼。节点增删后编号会自动重算，
指向的节点不会跑掉（有测试固定）。

### 一个必须知道的歧义

裸标签是连续字符串，所以 `[S NP VP]` 在记法里是**一个**叶子 `"NP VP"`，不是两个叶子。
要让 S 下面挂两个独立叶子，必须写 `[S [NP][VP]]`。

序列化器会据此决定写法：

- 唯一的女儿节点写作裸标签：`[A B]`
- 多个相邻叶子必须加方括号：`[S [NP] [VP]]`
- 含数字的多词叶子必须加引号（`"NP 5"`），否则会被切成 `NUMBER` + `STRING`
- 含 `->` 的多词叶子必须加引号，否则会被切成箭头 token

这些规则都有测试覆盖（`test/smoke.mjs` 的"往返保真"一节）。

## 设计要点

**单一真相来源是模型。** 文本面板只是模型的一个视图加一个输入通道：

- 图上有改动 → 模型 → 重新布局 → 重绘 → 回写文本
- 文本有改动 → 解析 → 换掉模型 → 重绘 → **不回写文本**

最后这条很关键：手打的写法可能和序列化结果不同（比如 `[S [A][B]]` vs 规范化后的 `[S [A] [B]]`），
如果每次都回写，光标会被打断，根本没法连续打字。

**选中态的映射。** `serialize()` 除了文本还会返回每个节点在文本里的字符区间
（`spans: Map<节点, [起, 止]>`），所以文本框里的光标位置可以反查成"最内层的那个节点"，
点文本框就能同步图上的选中。

**撤销很廉价。** 结构改动前把整棵树序列化成一小段文本压栈，撤销 = 重新解析。
所以不需要写复杂的反向操作，也就不会出现"撤销后状态不一致"这类 bug。

**渲染属性全部内联。** `render.js` 不依赖外部 CSS 决定颜色和线宽 —— 否则导出的 SVG
脱离页面就会变成一堆黑色填充块。CSS 只负责选中高亮、hover 和鼠标指针。

## 已知限制 / 可以继续做的

- **箭头不能在图上直接画**，只能在代码面板里写 `->1`。图上箭头能正确渲染、  结构变化时会自动重新编号，但没有"点两个节点连一条箭头"的交互。
- **三角形是隐式的**：规则是"叶子的标签含空格就画三角"。图上没有独立的三角开关，
  想造三角得在标签里打个空格。
- 从叶子加子节点会**清掉该叶子原有的箭头**（记法上无法表达"带箭头的节点"）。
  这个行为有测试固定住。
- 布局是每次全量重算。几百个节点没问题，上千个节点应该加增量布局。
- 没有拖拽。结构编辑走 Enter / Shift+Enter / Tab / Shift+Tab / Alt+←→ 和工具栏按钮；
  树的语义下"拖动自由摆放"通常不是想要的，所以没做。
- 导出 PNG 依赖浏览器把 SVG 光栅化，某些字体可能需要等 `document.fonts.ready`。
